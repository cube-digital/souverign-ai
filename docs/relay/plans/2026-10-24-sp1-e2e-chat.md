# SP1 — End-to-End Encrypted Chat Plan

**Goal:** four people in four browsers chat in groups, with attachments, through a relay that stores and forwards only ciphertext; Playwright proves it end to end.
**Spec:** docs/superpowers/specs/2026-10-24-sovereign-agents-demo-design.md (§4 A4, §5.4, §7, §8.1, §11 SP1, amendments 12–13) + docs/superpowers/specs/decisions.md. Mockups: docs/design/mockups/ (`Main.dc.html` is the reference for this plan).
**Architecture:** the browser holds a device key pair and the chat keys (IndexedDB). It encrypts every message with the chat key and talks to the **relay** (`services/relay`, WS + SQLite, sees only ciphertext) under `/relay`. The **bridge** (`services/bridge`, Fastify + Postgres) is the trusted directory: demo login with PIN, users, device public keys, chats and members. It tells the relay who is a member. The shared client logic (`packages/client`: relay link, key handling, encrypt/decrypt) also serves the bridge's agent devices in SP2.

**Prerequisite:** SP0 merged into `main` (this plan edits SP0's `Makefile`, `biome.json`, `.env.example`, `.gitignore`).

## Demo-first decisions (simplified on purpose — "it has to work as a demo")

- **Crypto, minimal:** one X25519 key pair per device (`crypto_box`), one XChaCha20-Poly1305 key per chat and epoch, chat keys delivered with `crypto_box_seal`. No signatures, no forward secrecy, no key-binding tricks.
- **Every membership change starts a new epoch** (add and remove). The member that changes membership (the chat owner) generates the new key and seals it for every current member device. So a newcomer can never decrypt older messages. This replaces the spec's "rotation on remove" and is the same code path.
- **Relay "auth" is a hello with the device id.** The relay enforces membership only: it accepts a message from a member and forwards it to members. The bridge sets membership through an admin endpoint protected by a shared token. There is no relay-side crypto at all.
- **Envelope kinds are `msg` and `key` only.** Attachments: encrypted bytes go up with `blob_put`; the `msg` body carries the blob id and its key. `presence` and `blob_ref` from the spec are dropped.
- **New devices do not get old chats.** A chat can only be created with members who already logged in once (have a device). A second browser for the same user starts empty.
- **Agent device hosting (`messages_plain`) moves to SP2.**
- **Same origin everywhere:** the web app calls `/api` (bridge) and `/relay` (relay) on its own origin. Vite proxies them in dev; `tailscale serve` does it in SP1.5. No `localhost` in client code.
- **Fonts are bundled** (`@fontsource/*`), never fetched from Google: the demo claims 0 bytes leave the Mac.
- **IndexedDB is namespaced per user** (`sa-keys-<userId>`), because the demo runs four users as four tabs of one browser.
- **Tests use PGlite** (Postgres in-process, `@electric-sql/pglite`), so `make check` and `make e2e` need no Docker. Dev and the demo use the Docker Postgres from SP0.

## Global Constraints

- TypeScript everywhere in this plan, packages scoped `@sa/*`, `"type": "module"`, each package exports its TS source (`"exports": {".": "./src/index.ts"}`); services run with `tsx`. No build step except `vite build`.
- Node-side packages use `module`/`moduleResolution` `NodeNext` from `tsconfig.base.json`: relative imports carry a `.js` extension (`import { x } from "./engine.js"`). The web app uses `Bundler` resolution.
- Every package keeps `typecheck` = `tsc --noEmit -p .` and `test` = `vitest run --passWithNoTests`. Tasks after T1 add files under `src/` and `test/` only and never touch `package.json` or `pnpm-lock.yaml`. If a task truly needs a new dependency, stop and report NEEDS_CONTEXT.
- Formatting: Biome (2 spaces, double quotes, semicolons, width 100). Run `pnpm format` and `pnpm lint` before each commit.
- Ports: web 5173, bridge 8647, relay 8648 (e2e: 5183 / 8657 / 8658). Bridge routes under `/api`, relay routes under `/relay`.
- UI copy in English. Colors, spacing and layout follow `docs/design/mockups/Main.dc.html` through the Tailwind theme in T4. No crypto jargon in the UI ("epoch", "seal"): say "can read messages from now on".
- Services log one JSON object per line to stdout (`{"level","msg",...}`) and never log message plaintext, keys or PINs.
- Commit messages `feat(sp1): …`, one commit per task.

## Review Focus

- No plaintext, chat key or file name reaches the relay: message bodies (including file names) live only inside `ciphertext`.
- The relay checks membership on send, on fanout, on sync and on blob get; a removed device stops receiving immediately; a device added later gets nothing older than its membership.
- A new member never receives an older chat key: every add and remove goes through `createEpoch`.
- The web client never hardcodes a host: only relative `/api` and `/relay` paths and `location`-derived WS URLs.
- The PIN, session token and device secret key never appear in logs; the session token is stored hashed in the bridge DB.

import { z } from "zod";

/** base64url without padding */
export const B64 = z.string().regex(/^[A-Za-z0-9_-]*$/);
export const Id = z.string().regex(/^[A-Za-z0-9_-]{8,64}$/);

export const MAX_BLOB_BYTES = 10 * 1024 * 1024;
export const MAX_CIPHERTEXT_CHARS = 350_000;

/** What travels through the relay. Everything private is inside `ciphertext`. */
export const Envelope = z
  .object({
    v: z.literal(1),
    id: Id,
    chat_id: Id,
    sender_device: Id,
    /** only for kind "key": the device the sealed chat key is for */
    to_device: Id.optional(),
    epoch: z.number().int().min(1),
    kind: z.enum(["msg", "key"]),
    nonce: B64,
    ciphertext: B64.max(MAX_CIPHERTEXT_CHARS),
    ts: z.number().int().nonnegative(),
  })
  .refine((e) => (e.kind === "key") === (e.to_device !== undefined), {
    message: "to_device is required for key envelopes and forbidden otherwise",
  });
export type Envelope = z.infer<typeof Envelope>;

export const ClientOp = z.discriminatedUnion("op", [
  z.object({ op: z.literal("hello"), device_id: Id }),
  z.object({ op: z.literal("send"), env: Envelope }),
  z.object({ op: z.literal("sync"), chat_id: Id, since: z.number().int().nonnegative() }),
  z.object({ op: z.literal("blob_put"), id: Id, chat_id: Id, data: B64 }),
  z.object({ op: z.literal("blob_get"), id: Id }),
]);
export type ClientOp = z.infer<typeof ClientOp>;

export const ErrorCode = z.enum(["bad_request", "no_hello", "not_member", "too_large", "not_found"]);
export type ErrorCode = z.infer<typeof ErrorCode>;

export const RelayOp = z.discriminatedUnion("op", [
  z.object({ op: z.literal("ready"), device_id: Id }),
  z.object({ op: z.literal("deliver"), seq: z.number().int().positive(), env: Envelope }),
  z.object({ op: z.literal("ack"), id: Id, seq: z.number().int().positive() }),
  z.object({
    op: z.literal("synced"),
    chat_id: Id,
    seq: z.number().int().nonnegative(),
    more: z.boolean(),
  }),
  z.object({ op: z.literal("blob_ok"), id: Id }),
  z.object({ op: z.literal("blob"), id: Id, data: B64 }),
  z.object({ op: z.literal("error"), code: ErrorCode, message: z.string(), ref: z.string().optional() }),
]);
export type RelayOp = z.infer<typeof RelayOp>;

/** POST /relay/admin/members, bridge only (Authorization: Bearer RELAY_ADMIN_TOKEN) */
export const RelayMemberChange = z.object({
  chat_id: Id,
  device_id: Id,
  op: z.enum(["add", "remove"]),
});
export type RelayMemberChange = z.infer<typeof RelayMemberChange>;

/** GET /relay/debug/recent: what the relay holds, for the "What the relay sees" panel */
export const RelayRecentRow = z.object({
  seq: z.number().int(),
  ts: z.number().int(),
  kind: z.enum(["msg", "key"]),
  chat_id: Id,
  sender_device: Id,
  to_device: Id.nullable(),
  size: z.number().int(),
  ciphertext_prefix: z.string(),
});
export type RelayRecentRow = z.infer<typeof RelayRecentRow>;

/** The plaintext inside a "msg" envelope. */
export const MessageBody = z.discriminatedUnion("type", [
  z.object({ type: z.literal("text"), text: z.string().min(1).max(8000) }),
  z.object({
    type: z.literal("file"),
    blob_id: Id,
    name: z.string().min(1).max(255),
    mime: z.string().max(127),
    size: z.number().int().nonnegative().max(MAX_BLOB_BYTES),
    key: B64,
    nonce: B64,
  }),
  z.object({ type: z.literal("system"), text: z.string().min(1).max(500) }),
]);
export type MessageBody = z.infer<typeof MessageBody>;

// Bridge API (/api)
export const UserSummary = z.object({ id: z.string(), display_name: z.string() });
export type UserSummary = z.infer<typeof UserSummary>;
export const LoginRequest = z.object({ user_id: z.string().min(1), pin: z.string().regex(/^\d{4,8}$/) });
export const LoginResponse = z.object({ token: z.string(), user: UserSummary });
export type LoginResponse = z.infer<typeof LoginResponse>;
export const DeviceRegistration = z.object({ device_id: Id, public_key: B64 });
export const DevicePublic = z.object({ device_id: Id, public_key: B64 });
export type DevicePublic = z.infer<typeof DevicePublic>;
export const DirectoryEntry = UserSummary.extend({ devices: z.array(DevicePublic) });
export type DirectoryEntry = z.infer<typeof DirectoryEntry>;
export const ChatMember = z.object({
  member_type: z.enum(["user", "agent"]),
  member_id: z.string(),
  display_name: z.string(),
  role: z.enum(["owner", "member"]),
  devices: z.array(DevicePublic),
});
export type ChatMember = z.infer<typeof ChatMember>;
export const Chat = z.object({
  id: Id,
  title: z.string(),
  kind: z.enum(["dm", "group", "room"]),
  created_by: z.string(),
  members: z.array(ChatMember),

export type Chat = z.infer<typeof Chat>;

});
export const AddMemberRequest = z.object({ user_id: z.string().min(1) });
export const ApiError = z.object({ error: z.string(), missing_devices: z.array(z.string()).optional() });
export type ApiError = z.infer<typeof ApiError>;

### T2: Crypto package

`packages/crypto/src/index.ts`, complete:

```ts
import sodium from "libsodium-wrappers-sumo";

/** Await once before any other call. */
export async function cryptoReady(): Promise<void> {
  await sodium.ready;
}

const V = () => sodium.base64_variants.URLSAFE_NO_PADDING;
export const toB64 = (bytes: Uint8Array): string => sodium.to_base64(bytes, V());
export const fromB64 = (text: string): Uint8Array => sodium.from_base64(text, V());

/** A device's X25519 key pair, base64url. The secret key never leaves the device. */
export type DeviceKeys = { publicKey: string; secretKey: string };

export function newDeviceKeys(): DeviceKeys {
  const kp = sodium.crypto_box_keypair();
  return { publicKey: toB64(kp.publicKey), secretKey: toB64(kp.privateKey) };
}

/** Stable 22-character id derived from the public key. */
export function deviceIdFor(publicKey: string): string {
  return toB64(sodium.crypto_generichash(16, fromB64(publicKey)));
}

export function randomId(): string {
  return toB64(sodium.randombytes_buf(16));
}

export function newChatKey(): string {
  return toB64(sodium.crypto_aead_xchacha20poly1305_ietf_keygen());
}

/** Encrypt a chat key so only the holder of `recipientPublicKey` can open it. */
export function sealKey(chatKey: string, recipientPublicKey: string): string {
  return toB64(sodium.crypto_box_seal(fromB64(chatKey), fromB64(recipientPublicKey)));
}

/** Throws if the key was not sealed for this device. */
export function openKey(sealed: string, device: DeviceKeys): string {
  const key = sodium.crypto_box_seal_open(
    fromB64(sealed),
    fromB64(device.publicKey),
    fromB64(device.secretKey),
  );
  return toB64(key);
}

/** `aad` binds the ciphertext to its envelope (chat, epoch, id); decrypt must pass the same. */
export function encrypt(
  chatKey: string,
  plaintext: string,
  aad: string,
): { nonce: string; ciphertext: string } {
  const nonce = sodium.randombytes_buf(sodium.crypto_aead_xchacha20poly1305_ietf_NPUBBYTES);
  const ciphertext = sodium.crypto_aead_xchacha20poly1305_ietf_encrypt(
    sodium.from_string(plaintext),
    sodium.from_string(aad),
    null,
    nonce,
    fromB64(chatKey),
  );
  return { nonce: toB64(nonce), ciphertext: toB64(ciphertext) };
}

/** Throws on a wrong key, a tampered ciphertext or a different `aad`. */
export function decrypt(chatKey: string, nonce: string, ciphertext: string, aad: string): string {
  const plaintext = sodium.crypto_aead_xchacha20poly1305_ietf_decrypt(
    null,
    fromB64(ciphertext),
    sodium.from_string(aad),
    fromB64(nonce),
    fromB64(chatKey),
  );
  return sodium.to_string(plaintext);
}

/** Attachments: a fresh key per file; the key travels inside the encrypted message. */
export function encryptBytes(data: Uint8Array): {
  key: string;
  nonce: string;
  ciphertext: Uint8Array;
} {
  const key = sodium.crypto_aead_xchacha20poly1305_ietf_keygen();
  const nonce = sodium.randombytes_buf(sodium.crypto_aead_xchacha20poly1305_ietf_NPUBBYTES);
  const ciphertext = sodium.crypto_aead_xchacha20poly1305_ietf_encrypt(data, null, null, nonce, key);
  return { key: toB64(key), nonce: toB64(nonce), ciphertext };
}

export function decryptBytes(key: string, nonce: string, ciphertext: Uint8Array): Uint8Array {
  return sodium.crypto_aead_xchacha20poly1305_ietf_decrypt(
    null,
    ciphertext,
    null,
    fromB64(nonce),
    fromB64(key),
  );
}

/** The AAD every message uses. */
export const messageAad = (chatId: string, epoch: number, envelopeId: string): string =>
  `sa/v1|${chatId}|${epoch}|${envelopeId}`;
```

If the ESM default import of `libsodium-wrappers-sumo` fails under Node or Vite, switch to the form that works for both (`import * as s from …` with `s.default ?? s`) and keep the exported API identical.

Tests (`packages/crypto/test/crypto.test.ts`, `await cryptoReady()` in `beforeAll`):

### T5: Relay

`services/relay`, plain `node:http` + `ws` + `better-sqlite3` (WAL), all routes under `/relay`.

- `src/server.ts`: `createRelay({ dbPath, adminToken, host = "127.0.0.1", port = 0 }): Promise<{ url: string; close(): Promise<void> }>`; `src/main.ts` reads `RELAY_DB` (default `<repo>/.run/relay.sqlite`, repo root resolved from `import.meta.dirname`), `RELAY_ADMIN_TOKEN` (required), `HOST`, `PORT` (8648).
- Schema: `envelopes(seq integer primary key autoincrement, id text unique, chat_id, sender_device, to_device null, epoch, kind, nonce, ciphertext, ts, received_at)`, `members(id integer primary key, chat_id, device_id, added_seq, removed_seq null)`, `blobs(id text primary key, chat_id, data blob, created_at)`. A device is an active member when a row with `removed_seq is null` exists.
- HTTP: `GET /relay/healthz`; `POST /relay/admin/members` (`RelayMemberChange`, bearer token compared in constant time, else 401): add inserts a row with `added_seq` = current max seq (no-op if already active); remove sets `removed_seq` = current max seq on the active row. `GET /relay/debug/recent?limit=50` → `RelayRecentRow[]`, newest first, `ciphertext_prefix` = first 48 chars.
- WS `/relay/ws` (`maxPayload` 16 MiB): the first op must be `hello` (else `error no_hello` and close); reply `ready`. Then:
  - `send`: sender must be the hello device and an active member; for `key`, `to_device` must also be an active member; else `error not_member` with `ref` = envelope id, and nothing is stored. Duplicate `id` → `ack` with the existing seq (safe retries). Store, `ack`, then deliver to every open socket of every active member (`key`: only to `to_device`), including the sender's.
  - `sync`: active member only; send `deliver` for envelopes of that chat with `seq > max(since, added_seq)` and (`to_device` null or me), ordered by seq, at most 500, then `synced {seq: last, more}`.
  - `blob_put`: active member of `chat_id`; decoded size ≤ `MAX_BLOB_BYTES` else `too_large`; store; `blob_ok`. `blob_get`: unknown → `not_found`; requester must be an active member of the blob's chat → `blob`.
- Log one JSON line per connection, send and membership change: ids, kinds, sizes only.

Tests (`test/relay.test.ts`, temp dir DB, port 0, raw `ws` clients):
- a non-member's `send` gets `not_member` and nothing is stored;
- a `msg` reaches every member socket; a `key` reaches only its `to_device`;
- a device added after message M does not get M on `sync`; a removed device gets nothing sent after its removal;
- plaintext check: send messages encrypted with `@sa/crypto` that contain five sentinel words, close the relay, and assert none of the sentinels (as UTF-8 bytes) occurs in the DB file or its `-wal`/`-shm` files.

### T6: Client engine

`packages/client`, isomorphic (browser and Node ≥ 22 global `WebSocket`). It holds everything a device does, so SP2's bridge-hosted agent devices reuse it.

- `src/keystore.ts`: `interface KeyStore { getDevice(): Promise<StoredDevice | null>; putDevice(d: StoredDevice): Promise<void>; getChatKey(chatId: string, epoch: number): Promise<string | null>; putChatKey(chatId: string, epoch: number, key: string): Promise<void>; latestEpoch(chatId: string): Promise<number>; getCursor(chatId: string): Promise<number>; putCursor(chatId: string, seq: number): Promise<void> }`, `StoredDevice = { deviceId: string; keys: DeviceKeys }`, plus `MemoryKeyStore`.
- `src/link.ts`: `interface RelayLink { send(env: Envelope): Promise<number>; sync(chatId: string, since: number): void; putBlob(id: string, chatId: string, data: Uint8Array): Promise<void>; getBlob(id: string): Promise<Uint8Array>; onDeliver(cb: (seq: number, env: Envelope) => void): () => void }`.
- `src/relay-client.ts`: `class RelayClient implements RelayLink`, `new RelayClient({ url, deviceId, WebSocketImpl? })`, `connect(): Promise<void>` (sends `hello`, resolves on `ready`), reconnects with backoff 0.5 s → 8 s and re-sends `hello`, then calls a `onReconnect` hook so the engine re-syncs. `send` resolves with the seq from the matching `ack` (by id) and rejects on an `error` whose `ref` is that id or after 10 s; `putBlob`/`getBlob` likewise via `blob_ok`/`blob`. `status` events: `connecting | ready | offline`.
- `src/engine.ts`: `class ChatEngine`, `new ChatEngine({ link, store, device })`:
  - `start(chatIds)`: `sync(chatId, cursor)` for each; again after every reconnect.
  - `createEpoch(chatId, devices: DevicePublic[]): Promise<number>`: epoch = `latestEpoch + 1`; new chat key; store it first; send one `key` envelope per device (including this one) with `ciphertext = sealKey(key, device.public_key)`, `nonce = ""`.
  - `sendText`, `sendSystem`, `sendFile({name, mime, bytes})`: encrypt the JSON `MessageBody` with the latest epoch's key and `messageAad(chat, epoch, id)`; files go up first with `putBlob` (encrypted with `encryptBytes`). No key → throw `Error("no_key")`.
  - `downloadFile(body)`: `getBlob` + `decryptBytes`.
  - Incoming: a `key` for this device → `openKey`, store, emit `onKey(chatId, epoch)`, then retry messages waiting for that epoch. A `msg` → skip if the id was seen; no key yet → keep it pending and emit it with `status: "pending"`; else decrypt, parse with `MessageBody`, emit `{ id, chatId, seq, ts, senderDevice, epoch, status: "ok", body }` (`status: "error"` when decryption or parsing fails). Always advance the cursor.
  - Listeners: `onMessage(cb)`, `onKey(cb)`, each returning an unsubscribe function.
- `src/index.ts` re-exports all of the above.

Tests (`test/engine.test.ts`, a `FakeRelay` in `test/fake-relay.ts` implementing `RelayLink` for several devices in memory with membership and seq order):
- two devices exchange text after `createEpoch`, and each sees both messages once;
- a device added later with a new epoch decrypts new messages and never receives the older ones (the fake relay mirrors the relay's membership window);
- a file sent by one device downloads byte-identical on another.
